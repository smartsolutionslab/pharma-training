# 0008: AI test draft: what the model sees and what it may return

**Status:** Accepted. The owner confirmed D1 on 2026-11-22.

## Context

- #21 (E8) drafts a course version's whole test with the project's model: questions "only about the chapters' content", distributed evenly over the chapters, as many as the test's blueprint asks, with no personal data sent. #22 (E9) applies the draft through `CourseVersion.ApplyAiTestDraft`, which keeps the approved questions and replaces the unreviewed ones.
- AGENTS.md treats a model's answer as untrusted input: it is parsed into a typed shape and checked like a request body. It also says to use `IChatClient`'s `GetResponseAsync<T>` for structured output, and lets an Application project reference `Microsoft.Extensions.AI.Abstractions` only (`ProviderSdksStayOutOfDomainAndApplication`).
- A chapter is Markdown text, a PDF or a video. A PDF or video chapter holds a blob reference, not content the system can read.
- ADR 0001 answers a missing model setting with `503 model-not-configured` and leaves provider errors at `500`.

## Decision

- **D1. Only text chapters are drafted from, and only their title and Markdown are sent.** PDF and video chapters are left out; "distributed evenly" applies to the text chapters. The editor adds questions about PDF and video chapters by hand. A version without a text chapter is refused before the model is called (`editorial.no-text-chapters`, 409). The draft's result names the chapters it left out (`TestDraft.LeftOutChapters`, in the version's order), so the editor knows; the UI shows them later.
- **D2. The draft asks for the blueprint's count less the approved questions** (since #245: less every question the draft keeps, see *Decided by the owner*). Applied, the test then holds exactly the blueprint's count, as `SubmitForReview` requires, and can never exceed `QuestionCount.Maximum`. When the approved questions already fill the blueprint, the draft is refused before the model is called (`editorial.nothing-to-draft`, 409).
- **D3. The even split is computed in code.** The requested count is split over the text chapters in the version's order, the remainder going to the first chapters (10 over 4 is 3, 3, 2, 2). The model is told each chapter's quota.
- **D4. Chapters are referenced by position.** The model sees the text chapters numbered 1…n and answers with that number; code maps it back to the chapter's id. No identifier of any kind (version, course, chapter, question) and no person is sent, and neither is the course's title.
- **D5. "No PII" means no data about persons.** Chapter titles and Markdown are editorial content written for every pharmacy and are sent as written. A unit test checks that a request carries no GUID and no person's id.
- **D6. Prompt placement.** The system message holds the instruction alone (`TestDraftPrompt.Instruction`, English, asking for output in the chapters' language). The user message holds the chapters as a JSON array between `<chapters>` and `</chapters>`, then the count and per-chapter quotas. JSON string escaping keeps a chapter's text from closing the delimiter, and the instruction says the chapters are data, never instructions. Content over `TestDraftRequest.MaxCharacters` (400 000 characters of titles and texts) is refused before the model is called (`editorial.too-much-content-to-draft`, 422).
- **D7. Structured output through Abstractions, checked by the module.** `GetResponseAsync<T>` lives in `Microsoft.Extensions.AI`, which Application may not reference, so the drafter sets `ChatOptions.ResponseFormat = ChatResponseFormat.ForJsonSchema<TestDraftAnswer>(…, "test_draft")` itself, deserializes the answer with `System.Text.Json` and checks it. This is the deliberate deviation from AGENTS.md's "use `GetResponseAsync<T>`". No temperature or top-p is set, since gpt-5 models refuse them. `ChatOptions.MaxOutputTokens` is set to 1,280 tokens a question asked for (`TestDrafter.MaxOutputTokensPerQuestion`), so a runaway answer is cut off instead of billed in full: a sound question with four options is some 150 to 250 tokens of JSON and gpt-5-mini counts its reasoning against the same limit, so that leaves ample room, yet 50 questions (`QuestionCount.Maximum`) stay at 64,000, half the model's own output ceiling. An answer cut off at the limit is unreadable (502).
- **D7 (continued): what rejects and what is accepted.** An answer that cannot be read (not JSON, a null, a missing property, an unknown type), has the wrong count, names a chapter that was not sent, or has a question or option text the value objects refuse, or more than `DraftedQuestion.MaxOptions` options, is rejected and nothing is returned to apply. A number written as a string (`"chapter":"2"`) is unreadable: numbers are read strictly. A chapter number that is not an integer literal (`1.0`, `2e0`) or lies outside `int` (`2147483648`) is unreadable too (502), although JSON Schema's `integer` admits the first two: `System.Text.Json` reads `TestDraftAnswerQuestion.Chapter` (`int`) strictly. Too few options or the wrong correct ones are accepted: the version reports them when the question is approved, and the editor fixes them. A per-chapter split that differs from the quotas, with the right total, is accepted and measured by the evals.
- **D7 (continued): one code for a rejected answer, `editorial.ai-draft-malformed`, 502.** The model, upstream, gave an unusable answer; the caller's request was fine. It has one constant English message; the defect (`TestDraftDefect`) travels on the failure value for tests and the eval transcript and is not shown to the caller.
- **D8. Provider failures are not wrapped.** An exception from the client (HTTP error, timeout, content filter) propagates and answers `500`, and a missing model setting `503`, as ADR 0001 says.
- **D9. The drafter is a static Application class taking `IChatClient` as a parameter.** `TestDrafter.DraftAsync(model, version, cancellationToken)` is what #22's handler, `ApplyAiTestDraftHandler`, calls with the `IChatClient` it takes by constructor; the evals call the same entry points, so the model sees the same request either way and no eval runs through the handler. Nothing is registered by hand.
- **D10. Applying the draft (#22).** `POST /editorial/course-versions/{id}/test-draft`, policy `editorial.edit`, no body, answers `200` with `EditorialTestDraftDto`: the drafted questions' ids, in the order the version now holds them, and the left-out chapters' ids, in the version's order. It is a POST because every call asks the model again and replaces the unreviewed questions (only the AI-drafted ones since #245), and a 200, not a 201, because nothing addressable is created; the editor reads the questions back with the version. The command `ApplyAiTestDraft` returns identifiers only, as CQRS logical asks: no question content and no count of the questions it replaced, which the UI warns about before the call from the version it shows. The handler loads the version once, tracked; the model is asked about that instance and its draft is applied to it (`CourseVersion.ApplyAiTestDraft` answers the drafted ids), then saved with `TryCommitAsync`. Nothing is held while the model answers: the `xmin` row version (ADR 0002) refuses the save if the version changed meanwhile, answering `409 editorial.course-version-changed`, which costs the model call; that is accepted. Every refusal that needs no model (not found, not a draft, no text chapter, nothing to draft, too much content) happens before the model is asked. No migration, and no new eval.
- **Evals.** The fabric sample use case `ask-the-model` is replaced in `tests/Evals/UseCases.cs` by `ai-test-draft`, whose examples are real course versions answered through the module's drafter, each with its chapters as grounding context. `TestDraftEvaluator` adds five metrics without a judge (chapter referenced, count matches blueprint, single choice has one correct, evenly distributed, accepted) and is added to `EvalRun`'s evaluators. The editorial module's own `AskTheModel` sample is removed.

## Decided by the owner

- **D1 confirmed (2026-11-22).** Only text chapters are drafted from. Drafting from a PDF or video chapter's title alone was rejected: questions are drafted only from content the model read.
- PDF chapters join through their extracted text in #157. Video chapters wait for transcripts.
- **A draft replaces every unreviewed question (2026-11-22)**, hand-written ones included, as the domain states. The page warns before the editor confirms, with the count of unreviewed questions it will replace. *Superseded on 2026-11-23, see below.*
- **A draft replaces only unreviewed AI-drafted questions (2026-11-23, #245)**, from the review of #241 (#199): the earlier rule made "change a setting, then AI-draft" wipe the whole test, since a settings change takes every approval away. Each question records how it came into its version (`QuestionOrigin`: `AiDraft`, `Copied`, `HandWritten`); copied and hand-written questions stay, even while unreviewed, and only need approving again. An editor's change keeps a question's origin. D2 follows: the draft asks for the blueprint's count less every question it keeps (approved ones, and copied or hand-written ones), so the applied test still holds exactly the blueprint's count, and `editorial.nothing-to-draft` answers when the kept questions fill it. The question DTO carries `origin`. Migration `RecordQuestionOrigin` classes existing questions: the database keeps no history of applied drafts, only provenance, which a copy keeps, so AI-drafted questions of a first version are `AiDraft` and every other existing question is `HandWritten`. The page's warning counting only the AI-drafted questions it will replace is a frontend follow-up.
- **The timeouts stay at their defaults (2026-11-22)**: the service's HttpClient attempt and total timeouts and the edge's proxy timeout, until a draft's latency is measured with a real model.
- **A per-editor rate limit on drafts is #174 (2026-11-22)**, not part of #22.

## Consequences

- PDF and video chapters get no AI questions until #157 (PDF) and transcripts (video); the editor writes theirs. The draft names them.
- A rejected answer costs a model call and changes nothing; the editor tries again.
- `fabric upgrade` may conflict on `tests/Evals/UseCases.cs`, `tests/Evals/EvalRun.cs`, `tests/Evals.Tests/EvalGateTests.cs` and `tests/Fakes/FakeChatClient.cs` (which now records each request's options). Keep this project's changes when resolving.
- Calling the drafter and its endpoint are done in #22 (D10). A draft's latency is bounded by the service's HttpClient timeouts and the edge's proxy timeout, at their defaults until measured with a real model; the answer's length by `MaxOutputTokens` (D7).
