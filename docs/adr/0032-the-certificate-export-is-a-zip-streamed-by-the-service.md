# 0032: The certificate export is a ZIP the service streams, chosen by employment period

**Status:** Accepted (#52).

## Context

- #52 (Z3) asks for a pharmacy manager's export of the pharmacy's certificates for a period, as a ZIP with the PDFs and a CSV index, holding only certificates from the time their holder worked in that pharmacy.
- ADR 0030 stores each PDF once at `certificates/{id}.pdf` in Certification's container (`DocumentLocation`), `Pending` until rendered, and says the export reads the same blobs.
- ADR 0002 keeps files from streaming through a service host and signs read URLs instead. That is about uploads and single downloads; a ZIP of many blobs does not exist in storage, so somebody has to assemble it.
- ADR 0003 decides per-pharmacy rights in the handler from the module's own copy of the caller's membership: a non-member gets 404, a member without the capability 403. Certification's copy kept no role yet. ADR 0015 orders a membership's states by version and foresaw that Certification may consume `MembershipChangedV1` the same way once it needs the current role.
- No deployed database exists (the owner's answer of 2026-11-23, quoted in ADR 0015 D2).

## Decision

- **Endpoint.** `GET /certification/pharmacies/{id:guid}/certificates/export?from=YYYY-MM-DD&to=YYYY-MM-DD`, `.RequireAuthorization()` without a realm-role policy (ADR 0003). The handler `ExportPharmacyCertificates` answers, the first failing check winning, and nothing read from blob storage before all pass: 403 `certification.identity-incomplete` without a person; 404 `certification.pharmacy-not-found` for an empty pharmacy id or without an active membership there; 403 `certification.capability-missing` unless every active membership there grants `Capability.ExportCertificates` (fail closed, as Compliance); 400 `certification.invalid-export-period` when `from` or `to` is missing, `to` is before `from` or after `from` plus five years (`DateOnly.AddYears(5)`, exactly five years allowed); 400 `certification.export-too-large` above 2000 certificates. A malformed date is the host's binding 400 without a module code.
- **Which certificates.** A certificate is exported when some membership of its holder in the pharmacy covers its `IssuedAt`, start inclusive and end exclusive (on the instant of leaving the person no longer works there), ended memberships included, so former staff's certificates from their time there are in; an ending without a stored start gives no period. Its issue day in Germany must lie in `from`..`to`, both inclusive, read as the instants from midnight in Germany at the start of `from` to midnight at the start of the day after `to`. A certificate earned while its holder worked in two pharmacies is in both exports. Order: `IssuedAt`, then id.
- **The ZIP is streamed by the Certification host and never stored.** `CertificateExportArchive` writes into the response body (`TypedResults.Stream`) with the async `ZipArchive` API (Kestrel forbids synchronous writes), `CompressionLevel.Fastest`, each entry dated by its certificate's `IssuedAt` (the index by the period's start), so the same data gives the same archive. Entry 1 is `index.csv`, then `pdf/{id:D}.pdf` per stored certificate, copied byte for byte through the new `IBlobReads` (`AzureBlobReads`, registered with the other blob services). This deviates from ADR 0002's "no streaming through a host" for this download alone; uploads and single PDFs keep their signed URLs. Nothing is written for retention either: since #53, retention is a cut-off on the pharmacy's view, applied in the export's query before the limit is counted, and nothing is deleted (docs/adr/0034). The archive's central directory is written only once every entry is complete (#367): a blob that cannot be opened or fails while it is copied ends the response with an exception after its `200` and headers went out, Kestrel and the edge abort the connection, and the bytes sent are no readable ZIP (no end-of-central-directory record), never a valid archive missing a PDF.
- **A pending PDF is visible, not silent.** Its row says `noch nicht erstellt` in the `PDF` column and the archive has no entry for it; one pending PDF does not block the export.
- **`index.csv`**: UTF-8 with BOM, `;`, CRLF, a header row, German headers like the PDF (`Bestätigungs-Id;Name;Schulung;Version;Ausgestellt am;Gültig bis;Ergebnis (%);Prüfcode;PDF`), dates `yyyy-MM-dd`, the issue date as the day in Germany. A name or course title (text people typed) starting with `=`, `+`, `-`, `@`, TAB or CR gets a leading `'` (formula injection); ids, numbers, dates and the verification code (base64url, which may start with `-`) stay verbatim. Then a field holding `;`, `"`, CR or LF is quoted with its quotes doubled (RFC 4180).
- **Certification copies the role.** `Membership` keeps `MembershipStartedV1.Role` (`MembershipRole`: `Manager`, `Employee`); `MembershipChangedV1Consumer` stores an insert-only `MembershipChange` per membership and version (at least 2) with the role alone, no name or job function (nothing for #115 to erase there). The current role is that of the change with the highest version, else the start's (ADR 0015). Manager grants every capability, Employee none. `MembershipChangedV1` is Organisation's, so it travels the broker; Certification's queue is bound by having the consumer (ADR 0011). Migration `AddMembershipRolesAndChanges` gives existing `certification.memberships` rows `role = 'Employee'` (fail closed); only local and test rows exist, and a local developer replays Organisation's events to restore managers.
- **Limits.** At most five years and 2000 certificates per export, so one request stays within the edge's timeouts and the host's memory holds one PDF at a time. The certificates are chosen in the database (the membership rule as `EXISTS` over `certification.memberships` and `certification.membership_endings`), and at most 2001 are read, so a refusal never loads more (#367).

## Consequences

- The Certification host carries the export's bytes; a very large export occupies one request for as long as storage streams. A stored or asynchronous export job is a new decision.
- A manager demoted or whose membership ended loses the export as soon as Certification has the change or ending; until then the previous role holds (eventual consistency, as Compliance).
- The column default `'Employee'` stays on `role`; the model always writes a role, so it applies only to the backfilled rows.
- Changing the CSV's columns or format changes a contract a pharmacy may have automated against; treat it like an API change.
- A failure after the first byte cannot change the status: the client sees a failed download (a browser's network error, `curl` exit 18 or 92, `HttpClient` throwing while it reads), and a partial file kept anyway is refused by every ZIP reader. Retrying the export is the remedy; nothing is left behind to clean up.
- The cap is enforced by reading at most `MaxCertificates + 1` certificates, so an export above it costs one bounded query whatever the pharmacy holds.
- A Certification database that held memberships before `AddMembershipRolesAndChanges` ran has them as `Employee`, so its managers get `403 certification.capability-missing` on the export until Organisation's `MembershipStartedV1` (and `MembershipChangedV1`) for them are delivered again. No database is deployed (ADR 0015 D2); a shared or staging database created before that migration needs those events republished before managers can export. Organisation has no republish for membership events today (unlike Editorial's, ADR 0019); building one is a new issue, opened only when such a database exists.
